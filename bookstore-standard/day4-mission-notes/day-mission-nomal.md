중급 — 출판사 요구를 열린 결정으로 기록하기
“출판사별 추천이 필요하다”는 요구를 검토하는 결정 기록 한 건을 작성하여, 현재 정상 6행·격리 7행 어디에도 출판사 컬럼이 없으므로 기존 다섯 엔터티를 임의로 늘리지 않고 필요한 원천 컬럼, 식별자 후보, 업무 규칙, 엔터티와 단순 속성을 가를 승인 조건을 명시한다.

완료 기준은 현재 고정 결과인 회원 4·카테고리 3·도서 5·주문 5·주문항목 6을 변경하지 않은 채 결론을 open으로 남기는 것이다.

# Day 4 중급 미션: 출판사 요구 결정 기록

## DR-001 출판사별 추천 요구

| 항목 | 기록 |
|---|---|
| 요구사항 | 출판사별 도서 추천이 필요하다 |
| 현재 상태 | OPEN |
| 현재 근거 | 정상 6행과 격리 7행에 출판사 관련 컬럼이 없다 |
| 필요한 원천 컬럼 | publisher_id 또는 publisher_code, publisher_name |
| 식별자 후보 | publisher_id |
| 영향 후보 | book과 publisher 사이의 관계 |
| 현재 결정 | 기존 다섯 엔터티를 변경하지 않는다 |

## 확인이 필요한 업무 규칙

1. 도서 한 종은 출판사 한 곳만 가질 수 있는가?
2. 공동 출판이 가능한가?
3. publisher_id는 원천 시스템에서 안정적으로 제공되는가?
4. 출판사명이 변경되어도 같은 출판사로 관리해야 하는가?
5. 출판사 정보는 모든 도서에 필수인가?

## 승인 조건

안정적인 publisher_id가 제공되고 여러 도서가 같은 출판사를
참조하며 출판사 자체 정보를 관리해야 한다면 publisher를
별도 엔터티로 승인한다.

출판사명 문자열만 필요하고 독립적인 관리가 필요하지 않다면
publisher_name을 book의 단순 속성으로 승인한다.

## 영향 분석

현재는 출판사 컬럼과 업무 규칙이 없으므로 결정을 OPEN으로
유지한다. entity-candidates.csv와 identifier-decisions.csv는
수정하지 않는다.

따라서 현재 고정 결과는 다음과 같이 유지된다.

- 회원: 4
- 카테고리: 3
- 도서: 5
- 주문: 5
- 주문항목: 6
